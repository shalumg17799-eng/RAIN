# Deploying __APP_ID__ to Azure

Generated by the PRD-to-App Factory (agent 5, QA & release).

## What gets created

| Resource | Purpose |
|---|---|
| Container Apps environment + Log Analytics | Hosts the app and collects its logs |
| Container App `__APP_DASH__` | The runtime: dashboards and governed AI questions (port 8080) |
| Container Apps Job `__APP_DASH__-provision` | Loads the App Pack's data and applies roles and row-level security |
| PostgreSQL Flexible Server, database `factory` | The app's data in schema `app___APP_ID__` |
| User-assigned managed identity | Pulls the image from the registry (AcrPull) |

## Deploy

```powershell
$env:AZURE_SUBSCRIPTION_ID = '...'; $env:AZURE_LOCATION = 'westus3'; $env:AZURE_RESOURCE_GROUP = 'rg-__APP_DASH__'
$env:AZURE_ACR_NAME = 'factoryacr123'; $env:PG_ADMIN_PASSWORD = '...'; $env:ANTHROPIC_API_KEY = '...'
./apppacks/__APP_ID__/deploy/deploy.ps1
```

The script builds the image in the registry (no local Docker), deploys `main.bicep`, starts the
provisioning job and prints the app URL.

## Sign-in (Entra ID)

Set `ENTRA_CLIENT_ID` and `ENTRA_CLIENT_SECRET` before deploying (an app registration with redirect URI
`https://<app-url>/.auth/login/aad/callback` and the "groups" claim enabled), and list each persona's
Entra group object ids in `apppacks/__APP_ID__/access.yaml`. Users then only see the personas their
groups allow. Without a client id the app runs with no sign-in and the persona is picked on the page:
demos only.

## Before production

- Move secrets to Key Vault references and the database to private networking.
- Confirm Claude model availability and data-handling terms (BAA if the data is PHI) for the chosen
  region; the runtime model is a parameter (`runtimeModel`).
